# Academy Strategy

## Purpose

Treat the AMD AI Academy Challenge as a learning-and-evidence program, not merely a final deadline.

The strategy is:

**Learn → Experiment → Build → Measure → Improve → Submit**

## Learn

Use AMD Academy material, ROCm resources, AMD Developer Cloud, and relevant technical sessions to improve actual AMD competence. Record completed work and practical lessons rather than collecting points without technical value.

## Experiment

Run small reproducible experiments before building a broad application. Candidate experiment families include:

- model/runtime bring-up;
- inference behavior;
- structured-output reliability;
- GPU/runtime operational behavior;
- framework compatibility;
- failure/recovery behavior;
- UCII authority-boundary integration experiments.

## Build

Progressively assemble the smallest real autonomous workload that demonstrates the UCII distinction on AMD infrastructure.

## Measure

Keep facts separate from interpretation. Where useful, record runtime versions, workload configuration, observed latency/performance, failures, quota/cost behavior, and reproducibility.

## Improve

Feed real AMD/ROCm and autonomous-workload findings back into the project architecture and, where genuinely applicable, into UCII engineering planning.

## Submit

The final submission should emerge from accumulated evidence. It should not merely be the first idea written at program signup.

## XP / leaderboard policy

Points and leaderboard position are useful signals and incentives, but they are secondary to durable engineering value. Pursue XP opportunities when they also produce learning, evidence, community engagement, or a better final project.

Do not manufacture low-value activity solely to increase a score.

## Competition separation

This repository is for the AMD AI Academy Challenge. `ucii-amd-authority-agent` is reserved for AMD Developer Hackathon ACT III. Reusable UCII core capabilities may serve both through public interfaces, but competition-specific implementation and evidence must remain clearly attributable to the correct event.
